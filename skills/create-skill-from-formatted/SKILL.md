# Create Skill From Formatted

Parses, evaluates, and optimizes an existing or imported formatted `SKILL.md` file. Ensures high discoverability when `disable-model-invocation: false` while minimizing context token overhead.

## Execution Workflow

### Step 1: Input Parsing & Body Audit
When given a formatted skill file or markdown string:
1. Parse existing frontmatter (`name`, `description`, `disable-model-invocation`).
2. Read and validate the complete `SKILL.md` body structure (`# Title`, `## Core rule`, `## When to ask`, etc.).
3. Ensure any execution/formatting details in `description` are fully present in the body.

### Step 2: Metadata Optimization (Delegated)
Delegate name & description optimization, token auditing, and trigger analysis to [`skill-metadata-optimizer`](../skill-metadata-optimizer/SKILL.md):
- Passes the skill body, current name, and current description.
- Receives the proposed token-optimized description (< 50 words), trigger analysis, and justification report.

### Step 3: Justification & Diff Report
Present the report generated by [`skill-metadata-optimizer`](../skill-metadata-optimizer/SKILL.md):
1. **Original Description** vs **Proposed Description**.
2. **Token Impact**: Original Word Count ➔ New Word Count (% reduction).
3. **Why the Change**: Exact details removed from frontmatter.
4. **How Mitigated**: Pointing to where those details live in the body.
5. **Discoverability Analysis**: Trigger coverage breakdown (User prompt, Workflow, Negative boundary).

### Step 4: User Review Gate (Mandatory)
Present the proposed changes to the user for review:
- If the user approves ➔ Apply the update to `SKILL.md`.
- **If the user says NOT to change ➔ Respect decision and leave original description intact.**
- If user requests tweaks ➔ Revise description accordingly.
